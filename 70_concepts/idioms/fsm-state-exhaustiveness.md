# One schema, three guarantees: FSM state exhaustiveness

## The idiom

When a state machine dispatches on `(state, event)`, the compiler can be made to enforce that every
state has an arm — so adding a state to the definition is a **compile error** until the code
handling it exists, rather than a silent fallthrough discovered in production.

## Why it was needed here

This is the clearest demonstration the polyglot port has, and it is nearly free: all three machines
are generated by `tools/codegen/fsm_codegen.py` from the *same* `schemas/fsm/order.fsm.yaml` — 13
states, 31 transitions. Same input, same generator, three different guarantees.

The failure this protects against is concrete. Someone adds `PENDING_AMEND` to the YAML. The
generator emits it as a state in all three languages. The question is what happens to the *dispatch*
code that has not been taught about it yet.

## What the naive version gets wrong

The naive generator emits a `default:` arm, because it is the obvious way to make the switch
compile:

```java
// Don't. This is the bug, spelled as caution.
switch (state) {
  case PENDING_NEW: ...
  case NEW: ...
  default:
    return TransitionResult.noTransition(state, ctx);   // ← PENDING_AMEND lands here
}
```

Now an order in `PENDING_AMEND` silently accepts no events. It does not throw, it does not log, it
does not fail a test — it sits there, and the first anyone knows is a trader asking why their amend
never came back. The `default` arm was written to be *defensive* and it is the thing that hides the
defect.

The Rust generator emits no catch-all across states. `PENDING_AMEND` fails to compile until its arm
is generated, at which point the generator has already emitted it — so the error surfaces during
`cargo build`, in the same commit that changed the schema.

Two things are worth being precise about, because it would be easy to overclaim:

- **The catch-all over *events* stays.** `_ => no_transition` inside each state's match is correct:
  a venue can send anything, and an unexpected event genuinely is "ignore it". Exhaustiveness is
  valuable over states, which are ours, and not over events, which are not.
- **C++ could get most of the way there.** `-Wswitch` errors on an unhandled enum value *if the
  switch has no `default`*. The existing generator emits one, so it does not today. That is a
  generator choice, not a language limit — the honest comparison is Rust "by construction" versus
  C++ "if you configure it and never add a default".

## Where it lives

`rust/ems-fsm/src/generated/order_fsm.rs:351` — `OrderFsmState::apply`, the exhaustive
`match self`. Compare `java/ems-fsm/src/main/generated/` and `cpp/fsm/generated/order_fsm.hpp`,
generated from the same YAML by the same script.

## Cross-language contrast

| | Dispatch | Adding a state to the schema |
|---|---|---|
| **Java** | `switch` with a `default` arm returning no-transition | Compiles. Fails at run time, silently — the order stops responding to events. |
| **C++** | `switch` with a `default:` label | Compiles. `-Wswitch` would catch it, but only with no `default`, and the generator emits one. |
| **Rust** | `match self { … }`, no catch-all over states | **Does not compile.** The build fails in the commit that changed the schema. |

The generator is the reason this comparison is clean: no one hand-wrote three dispatch tables and
made different choices. One script, one schema, three languages — and the difference in what each
language will let you get away with is the entire output of the experiment.

Two related properties fell out of writing the Rust emitter and are worth recording:

- **Payloads are a sum type, not a `void*`.** The C++ header takes `const void*` and
  `static_cast`s it to the payload struct the event is expected to carry. Rust takes
  `Option<&OrderFsmPayload>`, an enum with one variant per payload-carrying event, so handing
  `apply` the payload of a *different* event does not compile. See [[option-vs-nullable]] for the
  same shape at a smaller scale.
- **A missing payload is a no-transition, not a panic.** A transition whose guard reads a payload
  field cannot fire without one. Returning "nothing happened" rather than unwrapping means a
  truncated venue message is data, not a denial of service.
